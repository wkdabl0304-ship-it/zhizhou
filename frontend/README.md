# 知舟前端

使用 Vue 3、TypeScript 和 Vite 构建，使用 Vue Router 与 Pinia 组织页面和状态，使用 Reka UI 提供交互原语、Lucide Vue 提供线性图标。当前已采用青蓝水墨品牌方案，包含统一舟形 Logo、山海首页、明暗主题和公共组件，聊天页面已通过 SSE 实时展示进度正文、最终回答及工具/命令执行过程；尚未实现文件操作或知识库。

项目定位和功能规划见[根 README](../README.md)。

前端已接入注册、JWT 登录、当前用户校验，以及服务端会话列表、历史、续聊、自动标题同步、弹窗改名和软删除。首次聊天从后端取得 `conversation_id`，之后携带该 ID 继续会话；所有业务请求携带当前标签页的 Bearer 令牌。接口协议统一维护在[后端说明](../backend/README.md#认证与会话接口)，无需登录的界面样例可在开发模式 `/dev/ui` 查看。

## 环境与依赖

- Node.js 版本满足 `package.json` 的 `engines.node`：`^22.18.0 || >=24.12.0`。
- 使用 pnpm 管理依赖，仓库已有 `pnpm-lock.yaml`。

在 `frontend/` 目录执行以下命令：

```powershell
pnpm install --frozen-lockfile
pnpm dev
```

开发服务器的访问地址以终端输出为准。先按[后端开发说明](../backend/README.md#启动与聊天接口)准备配置、数据库并启动服务；Vite 开发服务器将 `/api` 请求代理到 `http://127.0.0.1:8000`，保留路径前缀。修改后端端口时同步调整 `vite.config.ts` 的代理目标并重启前端开发服务器。前端构建和环境文件不包含模型密钥。具备模型管理权限的账号登录后通过[模型管理](#模型管理)保存供应商连接、开启内置模型并设置全局默认，即可开始真实聊天。

生产构建使用同源 `/api`（包括 `/api/auth/*`），需要部署端将 `/api` 转发到后端，并关闭 SSE 响应缓冲以便实时交付增量；Vite 开发代理不包含在静态产物中，`pnpm preview` 也不提供此代理。

## 页面与聊天边界

后端已启用 RBAC 与资源范围。公开注册只创建普通用户，配置模型需先按[后端权限文档](../backend/docs/authorization-api.md)授予超管。当前前端尚未使用 `grants` 隐藏模型管理入口，也未提供用户、部门管理页面；无权限调用会收到 `40301`，普通聊天模型选择保持可用。

- `/login`、`/register`：在全幅山海背景上，以居中限宽的双栏组合品牌标题和表单，两者共用柔和底光；表单没有大块白色面板，输入采用半透明青灰底。背景独立覆盖页头、内容和页脚，不受正文宽度限制。支持明暗主题、山景缓移、流雾、水面光带、标题浮动水线及轻量入场，输入聚焦和按钮悬停有反馈。复用 `useMotionPreference`，系统减少动态效果时静态呈现，页面隐藏时暂停动画并在卸载时释放监听。手机改为上方品牌、下方表单，短屏自然滚动。注册成功返回登录并预填用户名，不自动登录；登录成功回到站内工作区，已登录访问认证页直接返回工作区。
- `/`：需登录的聊天工作空间，包含服务端会话目录、按需历史读取、流式聊天、消息复制与自适应输入区。点击侧栏品牌 Logo 或文字返回首页并清空未发送草稿，不删除已有会话；侧栏收起时 Logo 仍可点击。桌面侧栏可以收起，760px 及以下使用模态抽屉，返回首页时同步关闭抽屉。底部展示真实用户名并提供退出登录。
- `/dev/ui`：仅在 `pnpm dev` 中注册的组件预览页，展示按钮、提示、菜单、抽屉、长文本、等待、失败与禁用状态。生产构建不包含预览页面模块，访问此路径显示未找到页面。
- `/models`：需登录的模型管理页，登录后可返回该页面；从聊天侧栏或配置引导进入，使用方式见[模型管理](#模型管理)。
- 其他路径：显示未找到页面，提供返回首页入口。Web History 部署时需要将未知文件路径回退到 `index.html`，由前端路由识别页面。

账号规则与后端一致：用户名去除首尾空白并转小写，限定 3–32 位 ASCII 字母、数字或下划线；密码按 Unicode 字符计 8–128 位，保留首尾空格。确认密码仅前端校验，注册固定 `role=user`。请求等待时禁用重复提交，错误以文字提示，离开认证页会取消当前提交，迟到的登录结果不能恢复已放弃的身份。

`src/features/auth/` 的接口层调用 `/api/auth/register`、`/login`、`/me`；store 管理身份与有效期，路由守卫保护工作区。短期 Bearer 令牌及到期时刻存入当前标签页 `sessionStorage` 的 `zhizhou-auth`，不保存密码或用户信息；刷新后通过 `/me` 重新确认身份，临时网络失败显示重试入口，401 或到期清除登录。存储不可用时退化为本页内存登录。退出仅清除浏览器凭据，后端不提供刷新令牌或单独的退出接口；停用、改密会使旧令牌失效，详见[认证协议](../backend/docs/authorization-api.md#认证协议与前端授权)。同一账号在不同标签页独立登录和退出。聊天 store 监听身份变化，取消目录、历史及流式请求并清空缓存；旧请求的 401 不能退出后来登录的新账号，根组件负责回到登录页。

进入工作区时加载当前账号最近 20 个会话，侧栏在窗口恢复时自动同步，支持按游标加载更早目录；刷新页面后重新读取目录，默认回到新对话首页，不自动选择上次打开的会话。点击目录条目才读取该会话最近 20 轮历史，之后按需使用“加载更早消息”；重叠页按稳定 ID 去重，前插历史保持阅读位置。已加载的会话切换时复用内存缓存，窗口恢复时自动读取当前会话最近一页，用于同步其他窗口或服务重启后的状态。请求错误明确显示且可重试，不把失败当作空记录；历史未成功加载前禁止发送，避免在未核实的会话上误发。

点击新建不调用创建接口，也不生成业务 ID；只有发送消息时才创建会话，`start` 返回 `conversation_id / turn_id / is_new` 后绑定到侧栏。本地 `draft-*` 只用于首段到来前的消息展示，绝不发送给后端。首次请求未收到 start 时保留未确认的本地消息，不自动重发可能已落库的输入；可重新进入工作区或切回窗口，通过自动同步的目录确认服务端是否已建立会话。当前会话与正文不写入浏览器持久化存储。

会话标题由后端统一生成和保存。首次输入的临时标题按后端规则合并 Unicode 空白、取前 24 个字符；收到 `done` 后，前端单独读取会话元数据，将正式标题同步到侧栏和页头，不替换正文、不延长发送锁。自动同步失败保留原标题与成功回答，后续窗口恢复的目录同步仍可更新。侧栏铅笔入口、双击会话条目或聊天页标题均打开统一改名弹窗，生成期间也可操作；Enter 保存、Esc 取消并恢复焦点，中文输入法确认不会误提交。规范化后允许 1–100 个 Unicode 字符，按字符而非 UTF-16 长度计数；保存成功才更新显示，失败保留标题草稿并允许重试，同名保存仍会将标题确认成手动来源。每个工作区只打开一个会话操作弹窗，保存期间禁止重复提交、关闭和删除。当前操作对象在弹窗打开时固定，目录同步保留该条目；取消、保存或离页后清理编辑状态并恢复焦点。鼠标单击会短暂等待双击窗口，双击改名不触发导航，键盘选择立即执行。标题读写使用独立序号，较早的目录、历史或自动同步响应不能覆盖刚保存的手动标题，也不会回滚并行修改的模型选择。标题生命周期和接口见[后端标题说明](../backend/README.md#自动标题与手动改名)。

历史轮次复用实时消息的 Markdown 与工具时间线展示，保留公开参数、命令结果、失败和中断状态；部分正文不冒充最终回答。读到服务端 `running` 快照时不伪装为本页活跃连接，并暂时禁止续聊；每两秒自动同步当前会话，确认结束后恢复发送；切换路由、结束或卸载时停止轮询。当前没有 SSE 重放或断线续传。侧栏删除使用公共确认弹窗，默认聚焦取消，错误在弹窗内保留并支持重试；本页生成期间禁用删除，跨窗口生成冲突以服务端 409 为准；失败保留目录及正文，成功后移除条目，删除当前会话时回到首页并清空草稿。软删除的存储语义见后端文档。

前端通过 `delta / tool_call / tool_start / tool_end / tool_error` 将公开正文与工具按首次事件到达顺序交错显示，不再消费或展示模型推理。执行时正文直接显示，工具以紧凑摘要行显示名称、参数和状态，点击可查看完整输入与结果。收到 `done` 后，按 `done.message_id` 从时间线中移出最终消息的正文，以 `done.reply` 单独展示最终回答；之前全部行动说明和工具记录保留在“已完成 · N 项操作”入口中，自动折叠且可重新展开。普通聊天没有额外过程时不显示空入口；失败或断流时过程保持展开。整体折叠不清除单个工具详情的展开选择。

发送使用 `POST /api/chat`，首次请求体为 `{ message }`，续聊为 `{ message, conversation_id }`，通过 fetch 响应流消费正文与过程事件。适配层处理 UTF-8 和事件跨网络块的拆分，检查 HTTP 状态、SSE 类型、业务码、事件顺序、服务端会话及轮次标识、参数与结果类型；收到终止事件或退出账号后取消读取并释放流。详细协议只维护在[后端说明](../backend/README.md#启动与聊天接口)。

工具请求按 `tool_call_id` 关联，`tool_call` 仅显示“已请求，等待执行”，不宣称已经开始；`tool_start` 后才显示执行中，`run_id` 区分一次请求的多次执行，各次输入、结果和失败分别保留。并行工具按各自标识更新，不按工具名匹配。执行前拒绝的 `tool_error` 可以没有实际执行记录；单次工具失败不终止整轮，最终仍以 `done` 或顶层 `error` 为准。工具参数和输出按纯文本/格式化 JSON 展示，不执行 HTML。

命令卡片只依据后端明确返回的 `kind=command`，不根据名称猜测，也不在浏览器执行命令。当前后端不逐行转发 stdout/stderr，前端在开始时显示参数，在结束时显示完整公开输出。过程由后端持久化，重新打开会话时从历史快照恢复；收到最终回答时只移出与最终消息标识匹配的正文，其余记录完整保留。

等待首段时显示等待状态，正文增量按 `message_id` 分别累积到时间线并实时展示；工具调用前后的助手消息不会拼成同一段。只有 `done` 才确认完成，并以 `done.reply` 替换临时正文，随后允许复制回复。同一会话生成期间可编辑下一条草稿，但不能重复发送；切换会话不影响原请求的回复归属。

网络、HTTP、流内错误或协议异常均显示失败提示；流在 `done` 前结束也视为未完成。已接收的正文、执行记录、用户消息和当前草稿会保留，不自动重试或续传。未收到结果的工具在整轮结束时标记“未确认完成”，不推断是否已成功或失败；已有确定结果保持原状态。切换会话或新建时清空未发送草稿，旧请求更新仍归属原回复。正式页面不加载演示会话；`/dev/ui` 提供进度正文、工具、命令、运行中及失败样例，均不真实调用工具。

助手正文通过 `markdown-it` 渲染 Markdown，支持标题、加粗、斜体、删除线、有序与无序列表、引用、表格、链接、图片、分隔线、行内代码和代码块。流式生成时按当前累积源文重新解析，暂未闭合的标记随后续增量更新；用户输入保持纯文本。原始 HTML 标签转义为文本，危险链接协议由解析器过滤；新页链接设置 `noopener noreferrer`。表格与代码块独立横向滚动，适配明暗主题和窄屏。

代码块通过 `highlight.js` 对 JavaScript、TypeScript、Python、JSON、Bash、CSS、HTML/XML、SQL、Markdown 和 YAML 及其别名高亮，未知语言按纯文本展示。代码块可单独复制，不包含高亮标签；整条回复复制保留原始 Markdown。当前未添加数学公式或 Mermaid 图表扩展。`/dev/ui` 提供完整富文本样例，便于检查排版。

Enter 发送，Shift+Enter 换行；中文输入法组合输入及确认不会发送。输入框自动增高并在上限后内部滚动，消息滚动区域与底部输入区独立布局。用户消息气泡下方提供右对齐的“复制内容”按钮，与助手回复下方的复制按钮共用交互和反馈；助手生成期间也可复制已发送的用户内容。复制使用浏览器剪贴板 API，通常要求 HTTPS 或 localhost；失败时显示手动复制提示。

## 模型管理

模型管理与聊天共用工作区侧栏，跨页面保留会话目录、账户区域和折叠状态。顶部保留“MODEL PROVIDERS / 模型管理”中英双行标题及“模型供应商”一行，缩减标题区留白，不显示说明、刷新和返回聊天按钮；其下为 OpenAI、Anthropic、DeepSeek、阿里云百炼四张品牌卡片，未配置的供应商也展示。点击卡片打开居中弹窗：桌面左侧以连接卡片列表管理多份连接，点击卡片标题切换右侧模型；每份连接可独立启停，编辑表单在独立居中弹窗打开，新增连接入口常驻分区标题，“还没有连接”空卡片也可直接点击添加，并支持键盘和焦点恢复。右侧自动列出内置模型，参数摘要在模型卡片底部左侧，设为默认、高级设置、测试、删除直接排列在右侧，当前默认提供清除入口；测试结果仅在执行后显示在对应模型卡片内，模型列表下方不显示统一操作成功或失败通知。两个区域独立滚动，窄屏改为上下排列，模型底栏自动换行。编辑弹窗按连接信息、凭据或模型参数分组，长表单独立滚动，底部保存按钮固定可见；关闭时保护未保存草稿，并逐层恢复焦点。弹窗外框裁切内容，滚动条位于内部，标题和关闭入口保持可见，四角保留圆角。模型无需手动添加：首次打开开关时，以目录名称和默认推理参数自动保存配置；输出默认 16,384 tokens，并按目录上限和默认思考预算约束调整。开关保存成功后更新，失败保持原状态；启用不自动设置默认；设置、查看当前默认标记和清除默认都在模型行内完成，管理页顶部不展示默认摘要。窄屏卡片变为单列，侧栏导航入口位于紧凑标题行。目录及能力来自后端，并按已保存的接口格式重新读取，前端不维护另一份模型能力表。协议详见[后端模型配置](../backend/README.md#模型配置接口与两层适配)。

供应商 Logo 使用本地 SVG，来源为 [Lobe Icons](https://github.com/lobehub/lobe-icons) 的静态包 1.101.0，保留[原 MIT 许可](src/assets/providers/LICENSE.lobe-icons.txt)。只收录当前四家供应商的图形，不增加运行时依赖或外部图片请求；OpenAI 与 Anthropic 的单色图形适配明暗主题。

同品牌多份连接通过卡片标题切换；同模型的多份旧方案分别展示并保留原 ID、名称、参数和会话引用，不合并或迁移。已保存模型的“高级设置”通过独立居中弹窗编辑，可编辑名称、推理、输出与开放范围，不提供更换目录模型入口；测试与删除位于模型卡片底栏，测试点击即执行，删除仍需确认。删除模型配置后目录项保留为关闭，目录已移除的旧方案仍可停用和删除。

所有用户使用同一套全局模型配置，但仅获 model:manage 权限的账号可以管理；修改从下一轮聊天生效，不影响正在生成的一轮。连接与模型方案使用左右开关独立启停，点击即保存且不弹停用确认；重新启用连接不会修改子方案的开关；停用默认方案保留默认引用，但不会再作为可用初始选择。保存、测试、设置默认是独立动作；已停用且能力有效的方案仍可主动测试，点击测试立即发起请求，等待期间禁止重复操作，结果显示在原模型卡片；只验证文本流，不创建会话、不验证工具能力。测试结果只在内存中保留，并与模型及供应商版本匹配，配置修改后需重新测试。允许未测试但 `selectable` 的方案直接设为默认。

百炼供应商直接粘贴控制台的 **OpenAI 兼容地址（Base URL）**，不展示地域或业务空间输入。前端清除粘贴时附带的首尾空白及末尾斜杠，提示错误协议、原生 DashScope 地址或非官方地址，后端再次校验。管理面板展示已保存的完整 URL，长地址在窄屏自动换行。旧配置由后端转换为等价地址供编辑，密钥留空仍表示保留。完整协议及兼容策略见上方后端文档链接。

开发环境的模型配置 store 使用 Pinia 热更新入口替换动作和 getter，避免修改 API 解码后仍调用已挂载单例中的旧函数。更新时取消旧请求、停止旧身份监听，保留公开配置缓存及页面组件；迟到响应不能覆盖新版状态。首次从未支持此入口的旧页面升级时需手动刷新一次，刷新前先确认当前表单保存状态，避免重复创建。

密钥仅在当前供应商表单内存及本次写请求中出现，保存成功或卸载时清空；不写入 store 或浏览器存储，也不回显服务端密钥。编辑时留空保留凭据。所有更新与删除使用读取时的版本；冲突时自动同步公开快照并保留当前表单草稿，关闭后重新编辑才使用新版本。清除默认点击即执行；删除默认模型时先清除默认，再按模型版本删除，任一步失败停止后续操作，并说明默认已清除但删除失败的部分成功状态。仍有模型引用的供应商需先解除引用才能删除；保存中的表单禁止重复提交，有未保存内容时关闭、切换连接或离页需确认。

模型方案默认固定推理值；管理者也可开放受限自选，勾选允许的推理模式及原生档位、填写预算闭区间。方案自身具体值必须位于开放范围内，预算还需满足目录能力和输出上限约束。管理页不改变供应商目录，聊天仅展示后端 `/api/model-config/options` 返回的分组、顺序及允许范围。

聊天首页和已有会话在输入框右下角、发送按钮左边提供紧凑模型菜单，标题右侧提供“前往模型管理”，不重复显示未选择模型的提示；打开菜单自动同步允许范围，方向键仅浏览，明确选择后保存。输入框左下角使用单一思考强度入口，浮层显示当前值、模型名称与圆角滑块，不再额外提供思考开关。后端允许关闭时，滑块最左档即关闭思考；右移选择合法档位或预算，关闭后入口和浮层仍保留。固定策略只读，未开放关闭时最左档仍是允许的最低值。滑动时仅编辑草稿，释放或键盘确认后保存；预算也支持精确输入并校验整数范围，关闭浮层撤销未提交值。已有会话使用原选择版本 PATCH 保存；生成期间禁止更改模型与推理设置。

首页移除示例问题，输入区宽度上限 860px、空白输入高度 68px，保留上移后的布局；首页和会话共用输入组件。全站不提供常驻刷新按钮：目录与已保存会话在窗口重新可见时同步，模型选项在进入聊天、打开菜单及窗口激活时同步，返回管理后的选择仍保留。当前会话在其他页面生成时每两秒同步历史，结束、切换路由或卸载时释放轮询；本页生成中的消息不会被覆盖。失败状态保留必要的重试入口，不自动重发聊天或写入。

选项读取失败、选择失效或未确认预算时，保留草稿编辑与历史浏览，禁止发送并给出重选/重试入口。`40904`、`42201/42202` 等首轮提交前错误会撤回界面临时消息，保留消息与选择草稿，不自动重发；只有 `40901` 标记正在生成，只有 `40401` 标记会话不可用。草稿从聊天页前往模型管理再返回时保留，不跨刷新持久化；后端仍是实际执行配置的最终裁决。完整契约见[后端模型选择契约](../backend/README.md#模型配置接口与两层适配)。

## 公共样式与组件约定

正式界面采用青蓝水墨与“现代宋体”标题，保留文案“心有山海，自有知舟”，通过宋体笔锋、疏朗字距和青蓝强调线呈现品牌。`WelcomeHeading.vue` 承载首页标题，桌面字号上限 74px，窄屏使用 49px；宋体使用本机字体，跨设备字形可能不同，正文仍使用公共无衬线字体。浅色采用暖白纸面、清晰墨色与青碧主色，朱砂作为印记和次要强调；深色独立采用靛青画布、蓝灰界面层级、青玉操作色与月金辅助色，并保留侧栏收起、消息复制、主题记忆和窄屏抽屉。`BrandLogo.vue` 与 `RiverBackdrop.vue` 分别导入舟形和水墨素材。`ChatWelcome.vue` 组合首页视觉与真实输入区，不直接依赖会话 store。

首页水墨由 `RiverBackdrop.vue` 铺满整个主区域（含页头），与限宽标题和输入区独立；按容器比例裁切素材，窄屏也不会露出局部插图边框。山景以 14 秒单程周期漂移，双层流雾和水面光带以 7–9 秒单程周期错向移动；标题两行轻微错拍浮动，字形内的青蓝流光与强调水线独立播放，输入区保持稳定。进入对话正文后卸载首页背景和标题。`useMotionPreference` 管理首页动效：系统减少动态效果优先，页面隐藏时暂停动画（含伪元素上的雾带与水线）。页面和弹层统一使用根主题。明暗背景分别使用独立 PNG：浅色使用透明青蓝水墨，深色使用重新生成的月夜山海，不使用反相或色相滤镜。背景组件位于 `shared/components/RiverBackdrop.vue`，认证和聊天共用；夜景采用独立雾色、光带透明度与文字遮罩，图片尚未加载时只显示对应主题画布，减少切换闪烁。外观菜单用两张配色预览显示“青碧 · 朱砂”和“靛夜 · 月金”，保留浅色/深色语义、偏好记忆和收起入口，支持方向键浏览、Enter 确认和 Esc 取消。关键正文、辅助文字、主辅色及按钮文字组合由实际色板对比度测试检查，至少达到 4.5:1。水墨 PNG 由内置 imagegen 生成，Logo 为原创 SVG；素材与最终提示词见[生成记录](src/assets/brand/generation-notes.md)。基础组件预览页不进入生产包。

- `src/styles/tokens.css` 是设计变量的维护位置，统一颜色、字体、间距、圆角、阴影和层级。默认浅色；深色由根元素的 `data-theme="dark"` 启用。`zhizhou-theme` 是唯一写入 localStorage 的偏好，不保存聊天正文。
- `src/styles/base.css` 定义基础样式及共享 UI 外观。消息、侧栏、输入区等业务组件使用各自局部样式；业务组件引用语义变量，避免散落明暗配色。
- `src/shared/components/ui/` 提供按钮、图标按钮、自适应文本框，以及基于 Reka 的 Tooltip、DropdownMenu 和 Dialog 抽屉。使用方通过 props、事件和插槽组合；触发器使用 `asChild` 复用原生按钮，避免嵌套交互元素。
- 菜单、提示和抽屉内容通过 Portal 挂载，主题变量因此定义在文档根元素；共享弹层类不依赖页面祖先选择器。Reka 管理键盘、焦点及模态行为，包装组件负责外观和必要事件转发。
- 图标从 `@lucide/vue` 按需导入。图标按钮必须有可访问名称；抽屉必须提供标题和描述。动画遵循 `prefers-reduced-motion`。

### 测试分层与公共支撑

业务测试跟随模块，跨业务流程集中维护，浏览器流程独立运行：

```text
src/features/auth/__tests__/       # 认证接口、状态、校验和组件
src/features/chat/__tests__/       # 聊天事件、历史、api/、store/、components/
src/features/model-config/__tests__/ # 配置协议、目录规则、状态与编辑器组件
src/shared/__tests__/             # 公共组件、composables/、stores/、utils/
tests/integration/                # 真实 App、路由、身份与聊天状态协作
tests/e2e/                        # 真实浏览器和隔离后端的用户流程
tests/support/
  data/                          # 不依赖运行器的独立业务数据工厂
  vitest/                        # 组件与 Pinia 收尾、HTTP、SSE、浏览器替身
  playwright/                    # 独立账号、模型门控 fixture 与测试预览代理
  __tests__/                     # 公共测试工具自身的回归
```

Vitest 保持 4.1.11，配置 `modules` 和 `integration` 两个项目，默认执行两者。模块内允许按实际职责增加嵌套目录，不为规划中的业务预建空目录。只挂载聊天页面的测试放聊天模块；使用真实 App 和路由验证登录、退出与聊天清理的测试放 `tests/integration/`。测试文件按被测能力命名，辅助代码不得导入其他测试文件，生产源码不得依赖测试目录。

Vitest 使用 jsdom、契约一致的 fetch 替身及真实 ReadableStream，覆盖认证请求头合并、取消和迟到 401，聊天事件校验、分页与历史、工具交错和多次执行、跨账号隔离、资源释放、主题、输入法、Markdown 与包装组件事件。通过可控 Promise、流和事件推进异步场景。数据工厂每次返回独立对象；使用 `createTestPinia` 登记容器，公共 setup 先卸载组件并销毁状态，再恢复存储、DOM、时钟、spy 和全局替身。媒体查询和 ResizeObserver 等由需要的用例显式安装。

覆盖率通过同版本 `@vitest/coverage-v8` 收集 `src/` 下的生产 TypeScript 和 Vue，包含未被测试导入的文件，排除测试、类型声明和仅开发使用的预览。报告位于 `coverage/`，暂不设置百分比门槛；报告用于发现行为缺口，不以重复断言增加数量。

专项示例：

```powershell
pnpm test:unit --run src/features/chat/__tests__/store
pnpm test:integration
```

### 真实后端 E2E

首次安装依赖后安装 Chromium：

```powershell
pnpm exec playwright install chromium
pnpm test:e2e
# 额外参数传给 Playwright，可选择文件与项目。
pnpm test:e2e -- tests/e2e/chat.spec.ts --project chromium-desktop
```

E2E 还需要后端 uv/Python 依赖，以及可连接且有 CREATE DATABASE 权限的 PostgreSQL，配置方式见[后端测试](../backend/README.md#测试)。不需要启动开发服务或配置真实模型密钥。缺少数据库、依赖或浏览器直接失败，不跳过必要测试。

启动器 `backend/tests/support/e2e.py` 先构建生产产物，每次运行创建随机临时数据库并执行正式迁移。正式后端路由、异常处理、lifespan、业务服务、Agent 图和 PostgreSQL checkpoint 均参与验证，启动前通过正式服务在临时库写入假密钥和默认模型，仅替换部署测试配置与模型调用边界。每例使用独立账号、浏览器上下文和模型门控；正常流程使用真实认证、会话和聊天接口，仅在标题保存或删除的错误重试场景拦截指定请求注入 503，解除拦截后再验证真实写入。不访问真实付费模型，不修改开发库业务数据。模型等待和失败由仅存在于测试后端的授权控制通道推进，不依靠固定延时。

默认运行 `chromium-desktop`（1440×900）与 `chromium-narrow`（390×844），验证注册登录、受保护入口、刷新和退出、首轮与续聊、持久化历史、自动标题同步、生成中改名及刷新后保留、工具过程、流中失败、生成期间切换与取消、账号隔离、改名和删除弹窗的取消及失败重试、抽屉焦点与 Esc、切回桌面释放模态状态、主题记忆及生产包不开放开发入口。定位使用角色和可访问名称，断言自动等待；失败时保留 `test-results/` 下的截图与 trace，HTML 报告位于 `playwright-report/`，不维护像素截图基线。

随后运行 `model-config-desktop` 与 `model-config-narrow`，分别以同样桌面/窄屏尺寸验证真实配置闭环、推理预算、共享版本冲突、上游鉴权业务错误及删除引用约束；`model-selection.spec.ts` 同属这两个串行项目，验证无默认手选、刷新恢复、独立启停、受限档位/预算、多端选择冲突与生成中停用。这两个项目由依赖图串行执行，并在每例前后通过受本次控制令牌保护的共用 fixture 重置随机库配置，避免与先前的聊天场景互相影响。主动测试及聊天都仅替换模型供应商边界，业务 API 和存储保持真实。单独验证配置和选择时必须限制一个 worker：

```powershell
pnpm test:e2e -- tests/e2e/model-config.spec.ts --project=model-config-desktop --project=model-config-narrow --no-deps --workers=1
pnpm test:e2e -- tests/e2e/model-selection.spec.ts --project=model-config-desktop --project=model-config-narrow --no-deps --workers=1
```

终端会显示 Playwright 的逐项结果与汇总，例如 `18 passed`；失败时显示用例及错误详情。`pnpm test:e2e`、`pnpm test:all` 和 `pnpm verify` 均透传这些输出，命令以非零退出码表示失败。可执行 `pnpm exec playwright show-report` 打开最近一次 HTML 报告。

正常结束、测试失败、迁移或启动失败均按依赖顺序关闭浏览器和服务、连接，再删除本次创建的精确目标库。启动日志会显示临时库名称；强制终止进程可能留下该库，应依据本次日志确认后处理，后续测试不会扫描或删除其他临时库。启动器失败与资源清理另有后端自动化测试。

提交前运行改动相关测试，涉及导航、认证或聊天主流程时同时运行对应集成和 E2E；推送前运行 `pnpm verify`，并在后端执行 `uv run pytest -q`。仓库不自动接入 CI 或 Git hook。Firefox、WebKit、真实供应商模型以及字体和动画视觉效果仍需专项验收。

## 目录职责

- `src/main.ts`、`src/App.vue`：应用装配、公共样式、主题初始化、TooltipProvider 与身份失效后的路由回退。
- `src/router/`、`src/views/`：认证守卫、登录注册操作编排、聊天页面、开发预览与未知路径页面。
- `src/layouts/WorkspaceLayout.vue`：受保护的聊天与管理路由共用外壳，持有侧栏折叠、响应式抽屉、目录加载和导航状态；`ChatView`、`ModelManagementView` 仅维护各自主内容。页面间保留同一个布局实例，相关聊天组件测试通过真实路由挂载，跨页面状态回归放在集成测试与导航 E2E。
- `src/features/auth/`：认证专属外壳、表单、校验规则、HTTP 适配与 store；`authenticated.ts` 为业务请求添加 Bearer，并通知认证 store 处理当前令牌失效；认证模块不依赖聊天模块。
- `src/features/model-config/`：配置公开类型、API 解码、目录校验、启停、推理开放策略、全局默认和管理状态；`components/` 维护品牌卡片、供应商弹窗、目录模型行、独立居中供应商/模型编辑器及推理策略编辑器。`views/ModelManagementView.vue` 只编排页面导航和确认操作，密钥不进入共享状态；模块测试就近维护，跨聊天与认证的流程位于集中集成及 E2E。
- `src/features/model-selection/`：聊天安全选项、具体推理值及策略契约；纯解码/校验与可取消、按账号隔离的选项 store 不依赖聊天模块。模型菜单与独立思考强度浮层分别由 ChatModelSelector、ChatReasoningControl 承担，通过聊天 store 保存具体选择，聊天模块 API 复用契约解码版本与失效原因。管理模块复用纯策略类型和校验，不共享管理敏感数据到聊天选项。
- `src/features/chat/`：聊天与会话的完整业务模块。`components/` 维护侧栏、会话条目、消息、首页与输入区；`store.ts` 协调目录、分页历史、删除和流式续聊；`types.ts` 与 `chat-events.ts` 定义展示数据及公开事件契约。
- `src/features/chat/api/`：`stream.ts` 处理聊天 SSE 传输、会话及事件顺序校验，`conversations.ts` 处理会话 JSON 接口和游标，二者共同使用 `events.ts` 校验公开正文与工具事件字段，历史读取不依赖 SSE 传输实现。
- `src/features/chat/history.ts`、`activity.ts`：分别将持久化轮次转换为展示消息，以及归并实时或历史正文、工具执行与最终回答。聊天 store 保存原会话引用消费事件，并单独维护最终正文。
- `src/shared/components/`：舟形 Logo、主题预览菜单、共享山海背景和通用 Markdown 展示；`ui/` 提供按钮、受控开关、输入框、提示、菜单与弹窗等通用交互组件。
- `src/shared/composables/`、`src/shared/stores/theme.ts`：可清理的媒体查询、动效偏好和应用主题状态。
- `src/shared/utils/markdown.ts`：Markdown 安全选项、代码高亮与受控 HTML 渲染；共享 `MarkdownContent.vue` 负责展示样式和代码复制。
- `src/styles/`、`src/assets/`：设计变量、基础样式和构建处理的品牌素材；`src/dev/demo.ts` 保留开发演示会话数据，仅供开发组件预览，正式首页不展示示例。
- `src/**/__tests__/`、`tests/`：分别维护模块测试和集中集成、E2E、公共支撑，归属及运行方式见[测试分层与公共支撑](#测试分层与公共支撑)。
- `public/`：站点图标等无需构建转换的静态资源。
- `vite.config.ts`：构建与开发服务器配置，`@` 别名指向 `src/`。
- `vitest.config.ts`、`playwright.config.ts`：分别配置模块与集成测试、真实浏览器测试。

页面通过业务模块组织操作，业务模块依赖 `shared` 的公共能力；`shared` 不反向引用业务模块或路由页面。聊天通过认证模块发起带身份的请求，账号变化由聊天 store 监听并取消请求、清空缓存。新增业务代码放入对应 feature，通用能力确认不包含业务规则后再进入 `shared`，避免重新在顶层分散维护业务组件、接口、类型和状态。

提交依赖清单和 `pnpm-lock.yaml`；`node_modules/`、`dist/`、覆盖率输出和本地缓存按[根目录 `.gitignore`](../.gitignore) 的前端规则排除。

### 公共页面与弹窗组件

公共组件位于 `src/shared/components/ui/`，不依赖业务 store 或接口。`/dev/ui` 提供内容弹窗、确认框和不同按钮样式的交互示例，支持明暗主题检查。

| 组件 | 配置与用途 |
| --- | --- |
| `UiPageHeader` | `title / eyebrow / description` 组织标题层级；`size=sm/md/lg`、`level=1/2/3`、`align`、`serif` 和 `truncate` 控制构图与字体，`before / actions` 插槽承接导航和操作，暴露 `focus()`，通过 `titleDblclick` 报告交互。聊天、模型管理、未找到页面与组件预览已复用。 |
| `UiModal` | 受控 `open`，`size=sm/md/lg/xl`，可选 `height`；`layout=panel` 固定头尾、让业务内容管理内部滚动。默认插槽放内容，`footer` 放固定底栏，`header-actions` 补充次要操作。`busy` 阻止关闭；`closeOnEscape / closeOnOutside` 独立设置关闭策略；`initialFocus` 为内容内 CSS 选择器，`returnFocus` 指定恢复目标，`openAutoFocus` 支持精确聚焦。原 `wide / editor / drawer` 参数保留兼容。 |
| `UiDialogActions` | 统一取消、确认、等待和危险操作外观；`confirmLabel / cancelLabel / busy / disabled / danger` 配置状态，`form / confirmType=submit` 可提交内容区的独立表单，默认插槽显示简短辅助说明。 |
| `UiConfirmDialog` | 组合 `UiModal` 与 `UiDialogActions`；配置标题、说明、操作文案、危险样式、等待及错误，默认聚焦取消。`confirm` 只报告用户确认，由业务层执行操作，成功后更新 `open`，失败保留弹窗；会话删除、配置删除及放弃草稿均复用。 |

弹层通过 `useDialogLayer` 继承逻辑层级，Portal 不会破坏嵌套关系。通常无需手动设置层级；像会话弹窗宿主这样位于抽屉之外、需要覆盖抽屉的场景可显式传 `layer`。弹窗恢复焦点优先使用触发元素，触发器已被删除时回到剩余弹层或页面标题。业务取消和离页保护由调用方负责；公共组件不自动提交、丢弃草稿或关闭失败操作。

例如，表单放在默认插槽，公共底栏通过 `form` 提交：

```vue
<UiModal v-model:open="open" title="编辑资料" size="md" :busy="saving">
  <form :id="formId" @submit.prevent="save"><!-- 业务字段 --></form>
  <template #footer>
    <UiDialogActions :form="formId" confirm-type="submit" :busy="saving" @cancel="open = false" />
  </template>
</UiModal>
```

业务弹窗继续放在对应模块：`ConversationDialogs` 固定会话目标并调用改名/删除状态方法，`ConversationTitleEditor` 校验标题；模型配置编辑器保留自己的草稿和路由保护。通用确认、布局和按钮不再分散到业务 CSS。公共组件测试在 `src/shared/__tests__/components/`，业务回归就近维护，跨层流程位于 `tests/integration/` 和 `tests/e2e/`，E2E 的会话弹窗入口统一由 `tests/support/playwright/conversations.ts` 定位。
