# 知舟前端

使用 Vue 3、TypeScript 和 Vite 构建，使用 Vue Router 与 Pinia 组织页面和状态，使用 Reka UI 提供交互原语、Lucide Vue 提供线性图标。当前已采用青蓝水墨品牌方案，包含统一舟形 Logo、山海首页、明暗主题和公共组件，聊天页面已通过 SSE 实时展示进度正文、最终回答及工具/命令执行过程；尚未实现文件操作或知识库。

项目定位和功能规划见[根 README](../README.md)。

前端已接入注册、JWT 登录、当前用户校验，以及服务端会话列表、历史、续聊和软删除。首次聊天从后端取得 `conversation_id`，之后携带该 ID 继续会话；所有业务请求携带当前标签页的 Bearer 令牌。接口协议统一维护在[后端说明](../backend/README.md#认证与会话接口)，无需登录的界面样例可在开发模式 `/dev/ui` 查看。

## 环境与依赖

- Node.js 版本满足 `package.json` 的 `engines.node`：`^22.18.0 || >=24.12.0`。
- 使用 pnpm 管理依赖，仓库已有 `pnpm-lock.yaml`。

在 `frontend/` 目录执行以下命令：

```powershell
pnpm install --frozen-lockfile
pnpm dev
```

开发服务器的访问地址以终端输出为准。先按[后端开发说明](../backend/README.md#启动与聊天接口)准备配置、数据库并启动服务；Vite 开发服务器将 `/api` 请求代理到 `http://127.0.0.1:8000`，保留路径前缀。修改后端端口时同步调整 `vite.config.ts` 的代理目标并重启前端开发服务器。前端未配置模型密钥或其他后端凭据。真实聊天前需通过[后端模型配置接口](../backend/README.md#模型配置接口与两层适配)设置全局默认模型，配置页面尚未开发。

生产构建使用同源 `/api`（包括 `/api/auth/*`），需要部署端将 `/api` 转发到后端，并关闭 SSE 响应缓冲以便实时交付增量；Vite 开发代理不包含在静态产物中，`pnpm preview` 也不提供此代理。

## 页面与聊天边界

- `/login`、`/register`：在全幅山海背景上，以居中限宽的双栏组合品牌标题和表单，两者共用柔和底光；表单没有大块白色面板，输入采用半透明青灰底。背景独立覆盖页头、内容和页脚，不受正文宽度限制。支持明暗主题、山景缓移、流雾、水面光带、标题浮动水线及轻量入场，输入聚焦和按钮悬停有反馈。复用 `useMotionPreference`，系统减少动态效果时静态呈现，页面隐藏时暂停动画并在卸载时释放监听。手机改为上方品牌、下方表单，短屏自然滚动。注册成功返回登录并预填用户名，不自动登录；登录成功回到站内工作区，已登录访问认证页直接返回工作区。
- `/`：需登录的聊天工作空间，包含建议问题、服务端会话目录、按需历史读取、流式聊天、消息复制与自适应输入区。点击侧栏品牌 Logo 或文字返回首页并清空未发送草稿，不删除已有会话；侧栏收起时 Logo 仍可点击。桌面侧栏可以收起，760px 及以下使用模态抽屉，返回首页时同步关闭抽屉。底部展示真实用户名并提供退出登录。
- `/dev/ui`：仅在 `pnpm dev` 中注册的组件预览页，展示按钮、提示、菜单、抽屉、长文本、等待、失败与禁用状态。生产构建不包含预览页面模块，访问此路径显示未找到页面。
- 其他路径：显示未找到页面，提供返回首页入口。Web History 部署时需要将未知文件路径回退到 `index.html`，由前端路由识别页面。

账号规则与后端一致：用户名去除首尾空白并转小写，限定 3–32 位 ASCII 字母、数字或下划线；密码按 Unicode 字符计 8–128 位，保留首尾空格。确认密码仅前端校验，注册固定 `role=user`。请求等待时禁用重复提交，错误以文字提示，离开认证页会取消当前提交，迟到的登录结果不能恢复已放弃的身份。

`src/features/auth/` 的接口层调用 `/api/auth/register`、`/login`、`/me`；store 管理身份与有效期，路由守卫保护工作区。短期 Bearer 令牌及到期时刻存入当前标签页 `sessionStorage` 的 `zhizhou-auth`，不保存密码或用户信息；刷新后通过 `/me` 重新确认身份，临时网络失败显示重试入口，401 或到期清除登录。存储不可用时退化为本页内存登录。退出仅清除浏览器凭据，后端没有刷新或令牌撤销接口；同一账号在不同标签页独立登录和退出。聊天 store 监听身份变化，取消目录、历史及流式请求并清空缓存；旧请求的 401 不能退出后来登录的新账号，根组件负责回到登录页。

进入工作区时加载当前账号最近 20 个会话，侧栏可刷新或按游标加载更早目录；刷新页面后重新读取目录，默认回到新对话首页，不自动选择上次打开的会话。点击目录条目才读取该会话最近 20 轮历史，之后按需使用“加载更早消息”；重叠页按稳定 ID 去重，前插历史保持阅读位置。已加载的会话切换时复用内存缓存，“刷新会话”重新读取最近一页，用于同步其他窗口或服务重启后的状态。请求错误明确显示且可重试，不把失败当作空记录；历史未成功加载前禁止发送，避免在未核实的会话上误发。

点击新建不调用创建接口，也不生成业务 ID；只有发送消息时才创建会话，`start` 返回 `conversation_id / turn_id / is_new` 后绑定到侧栏。本地 `draft-*` 只用于首段到来前的消息展示，绝不发送给后端。首次请求未收到 start 时保留未确认的本地消息，不自动重发可能已落库的输入；可刷新目录检查服务端是否已建立会话。当前会话与正文不写入浏览器持久化存储。

历史轮次复用实时消息的 Markdown 与工具时间线展示，保留公开参数、命令结果、失败和中断状态；部分正文不冒充最终回答。读到服务端 `running` 快照时提示刷新，不伪装为本页活跃连接，并暂时禁止续聊；刷新确认结束后恢复发送。当前没有自动轮询、SSE 重放或断线续传。侧栏删除需要二次确认，本页生成期间禁用删除，跨窗口生成冲突以服务端 409 为准；失败保留目录及正文，成功后移除条目，删除当前会话时回到首页并清空草稿。软删除的存储语义见后端文档。

前端通过 `delta / tool_call / tool_start / tool_end / tool_error` 将公开正文与工具按首次事件到达顺序交错显示，不再消费或展示模型推理。执行时正文直接显示，工具以紧凑摘要行显示名称、参数和状态，点击可查看完整输入与结果。收到 `done` 后，按 `done.message_id` 从时间线中移出最终消息的正文，以 `done.reply` 单独展示最终回答；之前全部行动说明和工具记录保留在“已完成 · N 项操作”入口中，自动折叠且可重新展开。普通聊天没有额外过程时不显示空入口；失败或断流时过程保持展开。整体折叠不清除单个工具详情的展开选择。

发送使用 `POST /api/chat`，首次请求体为 `{ message }`，续聊为 `{ message, conversation_id }`，通过 fetch 响应流消费正文与过程事件。适配层处理 UTF-8 和事件跨网络块的拆分，检查 HTTP 状态、SSE 类型、业务码、事件顺序、服务端会话及轮次标识、参数与结果类型；收到终止事件或退出账号后取消读取并释放流。详细协议只维护在[后端说明](../backend/README.md#启动与聊天接口)。

工具请求按 `tool_call_id` 关联，`tool_call` 仅显示“已请求，等待执行”，不宣称已经开始；`tool_start` 后才显示执行中，`run_id` 区分一次请求的多次执行，各次输入、结果和失败分别保留。并行工具按各自标识更新，不按工具名匹配。执行前拒绝的 `tool_error` 可以没有实际执行记录；单次工具失败不终止整轮，最终仍以 `done` 或顶层 `error` 为准。工具参数和输出按纯文本/格式化 JSON 展示，不执行 HTML。

命令卡片只依据后端明确返回的 `kind=command`，不根据名称猜测，也不在浏览器执行命令。当前后端不逐行转发 stdout/stderr，前端在开始时显示参数，在结束时显示完整公开输出。过程由后端持久化，重新打开会话时从历史快照恢复；收到最终回答时只移出与最终消息标识匹配的正文，其余记录完整保留。

等待首段时显示等待状态，正文增量按 `message_id` 分别累积到时间线并实时展示；工具调用前后的助手消息不会拼成同一段。只有 `done` 才确认完成，并以 `done.reply` 替换临时正文，随后允许复制回复。同一会话生成期间可编辑下一条草稿，但不能重复发送；切换会话不影响原请求的回复归属。

网络、HTTP、流内错误或协议异常均显示失败提示；流在 `done` 前结束也视为未完成。已接收的正文、执行记录、用户消息和当前草稿会保留，不自动重试或续传。未收到结果的工具在整轮结束时标记“未确认完成”，不推断是否已成功或失败；已有确定结果保持原状态。切换会话或新建时清空未发送草稿，旧请求更新仍归属原回复。正式页面不加载演示会话；`/dev/ui` 提供进度正文、工具、命令、运行中及失败样例，均不真实调用工具。

助手正文通过 `markdown-it` 渲染 Markdown，支持标题、加粗、斜体、删除线、有序与无序列表、引用、表格、链接、图片、分隔线、行内代码和代码块。流式生成时按当前累积源文重新解析，暂未闭合的标记随后续增量更新；用户输入保持纯文本。原始 HTML 标签转义为文本，危险链接协议由解析器过滤；新页链接设置 `noopener noreferrer`。表格与代码块独立横向滚动，适配明暗主题和窄屏。

代码块通过 `highlight.js` 对 JavaScript、TypeScript、Python、JSON、Bash、CSS、HTML/XML、SQL、Markdown 和 YAML 及其别名高亮，未知语言按纯文本展示。代码块可单独复制，不包含高亮标签；整条回复复制保留原始 Markdown。当前未添加数学公式或 Mermaid 图表扩展。`/dev/ui` 提供完整富文本样例，便于检查排版。

Enter 发送，Shift+Enter 换行；中文输入法组合输入及确认不会发送。输入框自动增高并在上限后内部滚动，消息滚动区域与底部输入区独立布局。用户消息气泡下方提供右对齐的“复制内容”按钮，与助手回复下方的复制按钮共用交互和反馈；助手生成期间也可复制已发送的用户内容。复制使用浏览器剪贴板 API，通常要求 HTTPS 或 localhost；失败时显示手动复制提示。

## 公共样式与组件约定

正式界面采用青蓝水墨与“现代宋体”标题，保留文案“心有山海，自有知舟”，通过宋体笔锋、疏朗字距和青蓝强调线呈现品牌。`WelcomeHeading.vue` 承载首页标题，桌面字号上限 74px，窄屏使用 49px；宋体使用本机字体，跨设备字形可能不同，正文仍使用公共无衬线字体。界面使用冷白、深靛与青蓝色彩，并保留侧栏收起、消息复制、主题记忆和窄屏抽屉。`BrandLogo.vue` 与 `RiverBackdrop.vue` 分别导入舟形和水墨素材。`ChatWelcome.vue` 组合首页视觉与真实输入区，不直接依赖会话 store。

首页水墨由 `RiverBackdrop.vue` 铺满整个主区域（含页头），与限宽标题和输入区独立；按容器比例裁切素材，窄屏也不会露出局部插图边框。山景以 14 秒单程周期漂移，双层流雾和水面光带以 7–9 秒单程周期错向移动；标题两行轻微错拍浮动，字形内的青蓝流光与强调水线独立播放，输入区保持稳定。进入对话正文后卸载首页背景和标题。`useMotionPreference` 管理首页动效：系统减少动态效果优先，页面隐藏时暂停动画（含伪元素上的雾带与水线）。页面和弹层统一使用根主题。水墨 PNG 由内置 imagegen 生成，Logo 为原创 SVG；素材与最终提示词见[生成记录](src/assets/brand/generation-notes.md)。基础组件预览页不进入生产包。

- `src/styles/tokens.css` 是设计变量的维护位置，统一颜色、字体、间距、圆角、阴影和层级。默认浅色；深色由根元素的 `data-theme="dark"` 启用。`zhizhou-theme` 是唯一写入 localStorage 的偏好，不保存聊天正文。
- `src/styles/base.css` 定义基础样式及共享 UI 外观。消息、侧栏、输入区等业务组件使用各自局部样式；业务组件引用语义变量，避免散落明暗配色。
- `src/shared/components/ui/` 提供按钮、图标按钮、自适应文本框，以及基于 Reka 的 Tooltip、DropdownMenu 和 Dialog 抽屉。使用方通过 props、事件和插槽组合；触发器使用 `asChild` 复用原生按钮，避免嵌套交互元素。
- 菜单、提示和抽屉内容通过 Portal 挂载，主题变量因此定义在文档根元素；共享弹层类不依赖页面祖先选择器。Reka 管理键盘、焦点及模态行为，包装组件负责外观和必要事件转发。
- 图标从 `@lucide/vue` 按需导入。图标按钮必须有可访问名称；抽屉必须提供标题和描述。动画遵循 `prefers-reduced-motion`。

在 `frontend/` 执行；`pnpm lint` 和 `pnpm format` 会修改文件，验证使用只读的 `pnpm check:lint`。

| `pnpm test:e2e` | 构建前端、启动隔离后端与预览服务，运行全部 Playwright 测试 |

### 测试分层与公共支撑

业务测试跟随模块，跨业务流程集中维护，浏览器流程独立运行：

```text
src/features/auth/__tests__/       # 认证接口、状态、校验和组件
src/features/chat/__tests__/       # 聊天事件、历史、api/、store/、components/
src/shared/__tests__/             # 公共组件、composables/、stores/、utils/
tests/integration/                # 真实 App、路由、身份与聊天状态协作
tests/e2e/                        # 真实浏览器和隔离后端的用户流程
tests/support/
  data/                          # 不依赖运行器的独立业务数据工厂
  vitest/                        # 组件与 Pinia 收尾、HTTP、SSE、浏览器替身
  playwright/                    # 独立账号、模型门控 fixture 与测试预览代理
  __tests__/                     # 公共测试工具自身的回归
```

Vitest 保持 4.1.11，配置 `modules` 和 `integration` 两个项目，默认执行两者。模块内允许按实际职责增加嵌套目录，不为规划中的业务预建空目录。只挂载聊天页面的测试放聊天模块；使用真实 App 和路由验证登录、退出与聊天清理的测试放 `tests/integration/`。测试文件按被测能力命名，辅助代码不得导入其他测试文件，生产源码不得依赖测试目录。

Vitest 使用 jsdom、契约一致的 fetch 替身及真实 ReadableStream，覆盖认证请求头合并、取消和迟到 401，聊天事件校验、分页与历史、工具交错和多次执行、跨账号隔离、资源释放、主题、输入法、Markdown 与包装组件事件。通过可控 Promise、流和事件推进异步场景。数据工厂每次返回独立对象；使用 `createTestPinia` 登记容器，公共 setup 先卸载组件并销毁状态，再恢复存储、DOM、时钟、spy 和全局替身。媒体查询和 ResizeObserver 等由需要的用例显式安装。

覆盖率通过同版本 `@vitest/coverage-v8` 收集 `src/` 下的生产 TypeScript 和 Vue，包含未被测试导入的文件，排除测试、类型声明和仅开发使用的预览。报告位于 `coverage/`，暂不设置百分比门槛；报告用于发现行为缺口，不以重复断言增加数量。

专项示例：

```powershell
pnpm test:unit --run src/features/chat/__tests__/store
pnpm test:integration
```

### 真实后端 E2E

首次安装依赖后安装 Chromium：

```powershell
pnpm exec playwright install chromium
pnpm test:e2e
# 额外参数传给 Playwright，可选择文件与项目。
pnpm test:e2e -- tests/e2e/chat.spec.ts --project chromium-desktop
```

E2E 还需要后端 uv/Python 依赖，以及可连接且有 CREATE DATABASE 权限的 PostgreSQL，配置方式见[后端测试](../backend/README.md#测试)。不需要启动开发服务或配置真实模型密钥。缺少数据库、依赖或浏览器直接失败，不跳过必要测试。

启动器 `backend/tests/support/e2e.py` 先构建生产产物，每次运行创建随机临时数据库并执行正式迁移。正式后端路由、异常处理、lifespan、业务服务、Agent 图和 PostgreSQL checkpoint 均参与验证，启动前通过正式服务在临时库写入假密钥和默认模型，仅替换部署测试配置与模型 HTTP 边界。每例使用独立账号、浏览器上下文和模型门控；浏览器不模拟认证、会话或聊天接口，不访问真实付费模型，不修改开发库业务数据。模型等待和失败由仅存在于测试后端的授权控制通道推进，不依靠固定延时。

默认运行 `chromium-desktop`（1440×900）与 `chromium-narrow`（390×844），验证注册登录、受保护入口、刷新和退出、首轮与续聊、持久化历史、工具过程、流中失败、生成期间切换与取消、账号隔离、删除确认、抽屉焦点与 Esc、切回桌面释放模态状态、主题记忆及生产包不开放开发入口。定位使用角色和可访问名称，断言自动等待；失败时保留 `test-results/` 下的截图与 trace，HTML 报告位于 `playwright-report/`，不维护像素截图基线。

终端会显示 Playwright 的逐项结果与汇总，例如 `18 passed`；失败时显示用例及错误详情。`pnpm test:e2e`、`pnpm test:all` 和 `pnpm verify` 均透传这些输出，命令以非零退出码表示失败。可执行 `pnpm exec playwright show-report` 打开最近一次 HTML 报告。

正常结束、测试失败、迁移或启动失败均按依赖顺序关闭浏览器和服务、连接，再删除本次创建的精确目标库。启动日志会显示临时库名称；强制终止进程可能留下该库，应依据本次日志确认后处理，后续测试不会扫描或删除其他临时库。启动器失败与资源清理另有后端自动化测试。

提交前运行改动相关测试，涉及导航、认证或聊天主流程时同时运行对应集成和 E2E；推送前运行 `pnpm verify`，并在后端执行 `uv run pytest -q`。仓库不自动接入 CI 或 Git hook。Firefox、WebKit、真实供应商模型以及字体和动画视觉效果仍需专项验收。

## 目录职责

- `src/main.ts`、`src/App.vue`：应用装配、公共样式、主题初始化、TooltipProvider 与身份失效后的路由回退。
- `src/router/`、`src/views/`：认证守卫、登录注册操作编排、聊天页面、开发预览与未知路径页面。
- `src/features/auth/`：认证专属外壳、表单、校验规则、HTTP 适配与 store；`authenticated.ts` 为业务请求添加 Bearer，并通知认证 store 处理当前令牌失效；认证模块不依赖聊天模块。
- `src/features/chat/`：聊天与会话的完整业务模块。`components/` 维护侧栏、会话条目、消息、首页与输入区；`store.ts` 协调目录、分页历史、删除和流式续聊；`types.ts` 与 `chat-events.ts` 定义展示数据及公开事件契约。
- `src/features/chat/api/`：`stream.ts` 处理聊天 SSE 传输、会话及事件顺序校验，`conversations.ts` 处理会话 JSON 接口和游标，二者共同使用 `events.ts` 校验公开正文与工具事件字段，历史读取不依赖 SSE 传输实现。
- `src/features/chat/history.ts`、`activity.ts`：分别将持久化轮次转换为展示消息，以及归并实时或历史正文、工具执行与最终回答。聊天 store 保存原会话引用消费事件，并单独维护最终正文。
- `src/features/chat/suggestions.ts`：正式首页的建议输入，不创建演示会话，也不自动发送请求。
- `src/shared/components/`：舟形 Logo、主题菜单和通用 Markdown 展示；`ui/` 提供按钮、输入框、提示、菜单与抽屉等通用交互组件。
- `src/shared/composables/`、`src/shared/stores/theme.ts`：可清理的媒体查询、动效偏好和应用主题状态。
- `src/shared/utils/markdown.ts`：Markdown 安全选项、代码高亮与受控 HTML 渲染；共享 `MarkdownContent.vue` 负责展示样式和代码复制。
- `src/styles/`、`src/assets/`：设计变量、基础样式和构建处理的品牌素材；`src/dev/demo.ts` 保留开发演示会话数据，与正式首页建议分开维护。
- `src/**/__tests__/`、`tests/`：分别维护模块测试和集中集成、E2E、公共支撑，归属及运行方式见[测试分层与公共支撑](#测试分层与公共支撑)。
- `public/`：站点图标等无需构建转换的静态资源。
- `vite.config.ts`：构建与开发服务器配置，`@` 别名指向 `src/`。
- `vitest.config.ts`、`playwright.config.ts`：分别配置模块与集成测试、真实浏览器测试。

页面通过业务模块组织操作，业务模块依赖 `shared` 的公共能力；`shared` 不反向引用业务模块或路由页面。聊天通过认证模块发起带身份的请求，账号变化由聊天 store 监听并取消请求、清空缓存。新增业务代码放入对应 feature，通用能力确认不包含业务规则后再进入 `shared`，避免重新在顶层分散维护业务组件、接口、类型和状态。

提交依赖清单和 `pnpm-lock.yaml`；`node_modules/`、`dist/`、覆盖率输出和本地缓存按[根目录 `.gitignore`](../.gitignore) 的前端规则排除。
