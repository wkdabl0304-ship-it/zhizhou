# 知舟：产品定位与功能蓝图

> 本文记录产品方向与目标行为，不代表功能已经实现，也不作为数据库或接口设计。当前实现与启动入口见[根 README](../README.md)，模块细节见[后端说明](../backend/README.md)与[前端说明](../frontend/README.md)。

## 产品定位

知舟面向企业内部非技术人员，提供直接通过聊天使用的 AI 工作助手。员工用自然语言描述需求，智能体自动查找并阅读其有权访问的企业资料，给出结论与源文件出处；后续支持生成、修改文件。

交互借鉴 ChatGPT 与 Codex，工作环境和文档处理运行在服务器上。员工无需编程、配置本地开发环境或理解 RAG；管理员负责用户、部门、模型和共享资料的管理。

核心体验是：**直接聊天 → 自动查找授权资料 → 按需阅读 → 回答并引用来源 → 按需处理文件。**

## 当前基础与建设顺序

| 阶段 | 范围 | 状态 |
| --- | --- | --- |
| 工作区基础 | 登录、持久会话、流式回答、会话模型选择、模型管理、组织与范围权限 | 已有 MVP，具体边界以模块文档为准 |
| 企业资料问答 | 文件空间、会话附件、自动文档处理、授权检索、原文阅读、来源引用和无法解析文件的定位 | 下一阶段目标，尚未实现 |
| 文件协作 | 基于资料生成文件、修改授权文件、操作批准与文件版本管理 | 后续目标，尚未实现 |

已有组织权限仅作为后续文件授权的基础，不意味着现有管理员已经拥有文件管理能力。完整生产容器化部署仍在规划中。

## 文件空间与管理

文件统一分为三个空间，并通过目录组织。下表是目标权限原则，具体授权方式仍需设计。

| 空间 | 归属与默认读取范围 | 管理原则 |
| --- | --- | --- |
| 全局空间 | 企业共享资料，全员可读 | 超级管理员或获得对应授权的人员维护 |
| 部门空间 | 对应部门资料，在部门范围内隔离 | 部门管理员或获得对应授权的人员在授权范围内维护 |
| 个人空间 | 个人资料，默认仅本人可读 | 本人维护；管理员对个人内容的访问边界待确认 |

- 区分读取、上传、修改和删除权限；能读取共享文件，不代表能修改或删除。
- 超级管理员、部门管理员及获授权用户可在相应范围内整理文件和目录，处理重复、过时或错误资料。具体权限不单凭角色名称推断。
- 文件列表、检索片段、原文读取、预览、下载及引用入口均由后端校验当前权限；智能体遵循同样的边界。
- 用户只能选择有写入权限的目标空间与目录。用户离开部门或权限被撤销后，后续访问应按新权限执行。

## 聊天上传与文件去向

聊天上传时提供两种用途：

| 用途 | 用户操作 | 使用范围 |
| --- | --- | --- |
| 仅当前会话 | 上传附件并提问 | 仅服务当前会话，不进入长期文件空间，不向其他会话或用户开放 |
| 保存到文件空间 | 选择有写入权限的空间和目录 | 保存完整原文件，后台自动处理，之后可在授权范围内检索和使用 |

会话附件较长时，也可以进行解析、切分和临时检索。这不等于发布到共享知识库，也不要求将整个文件一次性放入模型上下文。

后台处理自动进行，用户无需配置切分长度、重叠比例或向量参数。界面应显示必要的处理状态，如处理中、可检索、处理失败或暂不支持内容解析；失败提供原因与适当的重试入口。

建议默认选择“仅当前会话”，并支持之后主动保存到文件空间；默认项及附件保留、清理规则仍待确认。

## 文件管理与 RAG 如何协作

采用“完整原文件 + 后台搜索索引 + 智能体按需阅读”的方向。原文件是资料依据，索引用于找到资料，用户不必额外维护另一套知识库。

切分只作用于后台提取的内容，不会把云文件拆成多个用户可见的小文件。每个检索片段应关联原文件、具体版本和可用的位置，例如章节、页码或工作表位置。

一次企业资料问答按以下目标流程协作：

1. 后端根据身份、部门及授权限定可访问资料范围。
2. 根据问题查找相关文件与内容位置，可结合文件名、目录、关键词和向量检索。
3. 智能体读取命中内容，并按需补读相邻段落、完整章节或文件；证据不足时继续搜索。
4. 根据资料组织结论，附带可核对的源文件出处及可用的原文位置。
5. 找不到依据、资料存在冲突或无法读取时，明确说明，不将推测描述成文档结论。

RAG 用于定位证据，不保证一次搜索就找齐全部资料。总结整份文件、跨文件比较等任务需要扩大阅读范围；数值统计需要读取实际数据并计算，不能仅凭几个检索片段下结论。

### 不同文件的处理目标

| 文件 | 目标行为与边界 |
| --- | --- |
| PDF、Word、文本文件 | 提取正文和可用结构，支持检索并关联原文件；位置引用使用实际可获取的章节、页码或段落信息 |
| Excel | 保留工作表、表头和单元格位置；涉及计算时读取相应数据，不将表格简单当作散落文本 |
| 扫描件、图片 | 尝试 OCR 或适配的视觉识别；失败或不支持时保留文件定位入口，并说明内容不可读取 |
| 暂不支持解析的视频等文件 | 保留文件名、目录、类型和已有描述，支持按这些信息查找并提供打开入口，不假装理解未解析的内容 |

无法解析文件的查找效果受名称和描述影响。缺乏有效描述的文件不能保证按内容找到；具体首批支持的格式、大小限制和识别能力待实现时确定。

### 文件与索引的生命周期

| 文件变化 | 目标检索行为 |
| --- | --- |
| 进入文件空间 | 自动解析并建立索引，完成后可参与内容检索；未完成时保留文件查找入口 |
| 内容更新 | 重新处理并更新索引，避免将不同版本混为同一份证据；处理中是否允许检索旧版本待确认 |
| 权限或空间变化 | 立即按新权限约束访问，同步更新索引中的范围信息 |
| 删除 | 立即停止后续检索和读取，后台清理对应片段、向量及其他衍生索引 |

即使索引清理尚未完成，后端也必须阻止已删除或已撤权文件的访问。文件删除不自动抹除已经生成的历史回答；其来源入口应反映已删除或当前无权访问的状态。

建议同一空间内对内容完全相同的重复上传提示已有文件；同名但内容不同的上传区分“更新版本”和“另存文件”。不同空间的相同内容不能因去重而合并权限或暴露其他空间的文件，去重与版本交互尚待确认。

## 后续文件操作与批准模式

智能体后续可结合企业资料生成文件，默认目标为用户个人空间；发布到共享空间须有对应写入权限，并明确目标位置。修改文件同样遵守授权与版本规则。

聊天界面计划提供“请求批准、帮我批准、完全信任”三种操作模式。以下是建议解释，具体触发条件仍待确认：

| 模式 | 建议行为 |
| --- | --- |
| 请求批准 | 对修改、删除或其他需要确认的操作，先展示对象和影响，等待用户批准 |
| 帮我批准 | 系统依据明确策略自动通过常规操作，需要用户决定的操作再发起确认 |
| 完全信任 | 在管理员允许和用户已获授权的范围内自动执行，不逐次请求批准 |

所有模式均不扩大数据访问范围。授权文档的普通查询和阅读默认自动执行；是否开放 Python、服务器命令、联网等能力，以及相应执行隔离方式，均未确定。

## 进入实现前的待决事项

- **文件授权**：普通成员能否向共享空间上传、如何授予维护权限，以及超级管理员能否访问个人空间。
- **会话附件**：默认用途、保留期限、会话删除后的清理及保存到空间后的引用关系。
- **重复与版本**：判重范围、同名文件交互、版本保留及更新处理期间旧版本的使用规则。
- **来源展示**：原文件预览、位置跳转和历史引用的版本查看方式。
- **文档处理**：首批格式与大小限制、扫描件识别、处理任务与失败重试，以及检索效果验收问题集。
- **文件操作**：生成与修改的首批格式、保存版本方式、批准模式及执行能力边界。

这些事项属于产品细化与后续技术设计，不表示需要先确定全部细节才能分阶段推进。具体框架、解析器、检索引擎与数据模型在对应功能设计中确定。
